# TP-V2-119 Precomputed Hourly Daily Read Model

Version: V2
ID: TP-V2-119
Status: done
Type: implementation
Depends on: TP-V2-118
Parallel with: none

## Goal

在数据真实、完整、可追溯的前提下，预先准备最近 30 天小时汇总和长期日期汇总，让用户打开网页、iPhone App 或 Widget 时直接读取展示结果，并尽量减少数据库读写。

## Context

GitHub Issue #47。常规用户查看不应临时扫描完整历史明细；汇总必须能处理迟到上报、重复上报和事实修正。

## Scope

- 新增最近 30 天的小时汇总和长期日期汇总读模型。
- 每次真实数据变更只更新受影响的小时桶和日期桶。
- 页面、移动摘要与 Widget 优先使用预汇总读模型，保留相同接口合同和筛选体验。
- 定时任务清理 30 天前小时汇总，并提供可验证的兜底重算路径。

## Out of Scope

- 不改变用户入口、登录态、采集来源、额度逻辑、Cloudflare 密钥或绑定。
- 不删除 canonical 小时事实，也不以缓存或估算替代真实事实。
- 不部署、迁移远程 D1 或修改生产资源。

## Red Test

- 先证明预汇总缺失时不会伪造结果，且补齐后与事实明细聚合相同。
- 先证明重复上报、迟到上报和数据修正不会重复或漏记。
- 先证明清理旧小时汇总后，长期日期趋势和历史总量仍正确。

## Implementation

1. 定义小时/日期汇总表、唯一维度与 30 天保留策略。
2. 让写入路径在事实发生实质变化时增量刷新受影响桶，并提供有界回填。
3. 让读取路径优先使用汇总表；结果与现有接口合同一致。
4. 增加定时兜底校正、清理和完整测试。

## Acceptance Criteria

- 最近 30 天最多约 720 个小时桶可用于今天走势、近期回看和修正。
- 本周、本月和全部历史趋势使用长期日期汇总。
- 相同数据下，网页和移动端各周期、各筛选条件结果与现有结果一致。
- 用户常规查看不再临时扫描完整历史小时事实。
