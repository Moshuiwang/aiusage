# 测试反欺骗判例集

骨架四条在 `AGENTS.md`「测试自身也会骗人」；本文是配套历史判例（2026-08-01/02 两次交付
各命中过至少一次），写断言前对号入座。

## 变异证据

- 变异集要覆盖**绕过路径**而不只是正面路径：出过治理断言只变异了相对导入，
  绝对导入能直接穿过去。
- 变异用文件备份还原，**不要用 `git checkout --`**——它会连未提交的改动一起冲掉。
- 绿有两种含义（守卫有效 / 注入没生效），二者无法区分——红才是变异证据：
  先确认注入真的生效（看到预期的红，或打印注入后的实际值），再谈还原回绿。

## golden 与 fixture

- 从实现生成的 golden 若没有「重新生成并比对」的测试，会在某天静默停止守护任何东西；
  跨实现 parity 会因为「两边都没有新字段」继续报绿。
- 手写 fixture 会和现实脱节，方向正好是「实现者以为的样子」：出过 fixture 里带着
  读模型永远产不出的字段。
- **fixture 覆盖不到的场景等于没有断言**：出过某字段只在一种失败形态下发送，
  fixture 没有那个场景，「顶层字段必须被声明并解析」的断言对它完全瞎。

## 「通过」的结构下限（真实反例）

- parity 比对无结构下限——「什么都没检查」和「检查了且全过」产生同一个绿。
- health 对「后端根本没返回版本块」判通过；302 登录页被判成健康。
- 凭据守卫压根没执行到凭据路径。
- 合同比对里 14/16 条只校 status 与 content-type，连「这条记录在 golden 里存不存在」都不查。

## 恒真断言与守恒复算

- 凡是「断言某物不存在 / 为 None / 不在里面」的写法，先问：正确实现下它本来就不可能
  存在吗？是的话这条断言永远为真，删掉或换对象。出过：断言一个条目里根本没有的 key 为
  None；断言两个由同一构造产出的对象相等。
- 守恒等式、口径一致性从最终产物独立算一遍，不要跑被测代码自己的断言；恒等式一旦选错
  对象（断言一个恒成立的式子），测试和实现会一起错（#89 provider slots parity 是最低判例）。

## 差异路径名会骗人

某条差异叫 `items|len` 不代表它是「数量差」——可能是口径差穿过去重/聚合逻辑之后的投影。
把差异归类成「已知无害」之前，**从两侧产物各自把那个值算出来看一眼**，不照路径名推断根因。
